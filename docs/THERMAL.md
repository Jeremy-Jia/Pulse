# 小米 15 / 18 Pro CPU 温控策略

Pulse 1.5 保留原有监测、悬浮窗、小部件和性能实验室，从首页「温控」进入。连接 Root 只验证权限和固件，点击「应用策略」才修改。不提供提权、BL 解锁或刷分区。

## 支持范围

| 设备 | 已匹配固件 | CPU 频率域 | 普通频率表上限 |
| --- | --- | --- | --- |
| Xiaomi 15 / dada | OS4.0.0.19.XOCCNXM.D01 | CPU0–5 / CPU6–7 | 3.5328 / 4.32 GHz |
| Xiaomi 18 Pro / hongkong | OS4.0.24.0.XFRCNXM | CPU0–2 / CPU3–5 / CPU6–7 | 3.744 / 4.032 / 4.704 GHz |

18 的 CPU6–7 还支持 4.8576 / 4.9536 / 5.0112 GHz 三个 Boost 档，均可选择。应用前另查 Boost 表与全局/策略 Boost 开关。普通表和 Boost 表分开校验；恢复时释放自身频率上限至驱动的 5.0112 GHz，不额外限制原厂 Boost。能够选择不等于能持续达到。

需要为 Pulse 单独授权 Root。检查温控程序、原厂密文、解码明文 SHA-256 和全部频率表，未知固件拒绝修改。频率域不单凭频率高低推断微架构。没有新增独立应用、广告或网络权限。

## 频率策略

- 全频：每个温度档使用该组所选上限。
- 阶梯增强：0–100%，25°C 档使用所选上限，其余档按增幅计算，向下取支持的频率。
- 逐档自定义：15 为 14 / 16 档，18 为 7 / 7 / 8 档；提供原厂、全频、当前增幅填充。

这是允许上限，不强锁频率、不添加超过普通驱动表的超频档。档位使用系统估算机身温度；原有触发温度、回落滞后、GPU、充电、Thermal HAL、内核与芯片保护保持。调度、电流、功率与芯片温度仍可能限频。

## 温度与持续运行

电池、估算机身停止线可设 35–50°C，可额外启用 CPU 热点停止线 70–110°C。默认电池 45°C、机身 43°C、额外 CPU 线关闭。这些是 Pulse 退出条件，不是测得的硬件极限。触线恢复并停止，之后需手动重新启用。

定时模式为 1–1440 分钟；持续模式无倒计时。退出界面、后台冻结或返回前台本身不停止 Root 守护。15 保留「重启后继续」：开机先恢复再校验重启；手动或触线停止的会话不会再次启动。

18 当前使用临时 Root，禁用开机继续。全局挂载命名空间中的临时绑定目录覆盖配置路径，原厂物理目录保持为空；重启后挂载消失，不依赖重启后仍有 Root 执行恢复。

持续模式遇到其他系统场景配置时暂停，保留温度守护和手动恢复；仅在已验证普通配置返回后继续，不向游戏或充电配置强行写入普通曲线。定时模式遇到未知配置仍停止恢复。场景数值变化但配置未变，不再无条件停止。

## 状态与恢复

返回前台主动重新读取 Root 状态，首次读取之前不把未知状态显示为已停止。Root 进度与错误在全部温控子页显示。旧会话需先恢复才能升级控制器时，恢复按钮仍可操作。

前台通知显示温度、计时和恢复操作。Root 主守护及独立第二守护不依赖界面；Android 冻结可能延迟通知刷新。CSV 包含各组频率、上限、温度、电流、电压、场景和状态。电池净功率不等于 SoC 功率。

运行资料位于 `/data/adb/pulse-thermal`。APK 与源码不包含厂商程序、完整配置、密钥或设备备份。15 从匹配程序读取编码材料；18 加载其用户态私有副本，禁用副本构造函数，仅调用固定且经过验证的初始化函数，临时文件用后删除。两种适配均要求原厂往返逐字节一致。

只修改普通配置中的 CPU `target` 行，加载后核对实际明文哈希，失败恢复。15 使用启动恢复脚本；18 使用重启即消失的挂载。恢复只移除 Pulse 自己的覆盖和挂载。卸载前请先恢复原厂。

在 Android Root shell 中恢复当前会话：

```sh
id=$(cat /data/adb/pulse-thermal/current)
/system/bin/sh /data/adb/pulse-thermal/runner.sh restore "$id" MANUAL
```

## 验证

`tools/ThermalCodecTest.java` 回归 15 历史配置逐字节一致；`Thermal18CodecTest.java` 验证三组曲线、各增幅、自定义及其他保护不变。本地固件和临时编码材料不入库。

18 的硬件测试：`adb shell am instrument -w -e thermal true -e thermal_scope mi18 dev.pulse.monitor.test/dev.pulse.monitor.MonitorInstrumentation`。会应用有停止线的策略，先恢复已有会话，并保持 Pulse 前台，避免 HyperOS 暂停测试线程。检查真实 Root、全局挂载、状态同步、一分钟计时、守护异常恢复、原厂哈希和空覆盖目录。真实重启不以模拟检查代替。

详见 [1.5 记录](verification/thermal-1.5.0/REPORT.md)；15 此前硬件证据见 [1.4 记录](verification/thermal-1.4.0/REPORT.md)。
