# 小米 15 CPU 温控策略

Pulse 1.4 在原有监测、悬浮窗、小部件和性能实验室之外新增温控子页。从首页右上角「温控」或「CPU 温控策略」卡片进入，左上角返回 Pulse。日常监测仍是只读；只有点击温控页的「应用策略」才开始修改。

## 支持范围

仅适配已在本机验证的 **Xiaomi 15 / dada，HyperOS 4.0.0.19.XOCCNXM.D01 / Android 17 温控版本**。实际准入同时验证手机温控程序、原厂加密配置和解码后的配置 SHA-256；不单凭系统版本字符串判断。其他机型、Root 不可用、编码方式不匹配或更新后的未知配置都会拒绝修改。Pulse 的其他功能照常使用。

需要在 KernelSU 为 **Pulse** 授权 Root。没有新增独立应用、广告、分析服务或联网权限。

## 三种频率策略

- **全频释放**：两组核心在所有现有温度档采用各自选择的上限。默认 CPU0–5 为 3.5328GHz，CPU6–7 为 4.32GHz。
- **阶梯增强**：增幅可在 0–100% 之间逐百分比设置。25°C 档使用所选上限，其余档以原频率乘以 `1 + 增幅`，向下取设备支持的频率，并限制在所选总上限以内。25% 只是一个预设。
- **逐档自定义**：分别编辑性能核 14 档、超大核 16 档的上限；提供「原厂」「全频」「当前增幅」填充，再逐档选择真实频率表内的值。只有原厂完全不变的曲线不会启动修改，可直接保持原厂策略。

CPU0–5 是性能核，CPU6–7 是超大核，此芯片没有传统意义的低功耗小核。曲线档位使用系统的**估算机身温度**，不是 CPU 芯片温度；原来的触发温度、回落滞后与其他控制项保持不变。

设置的是允许上限，不是强制锁定实际频率。调度、芯片温度、电流、功率及其他系统约束仍可能降低实际频率；本功能不添加超过驱动频率表的超频档。

## 温度与退出条件

可设置电池停止线 35–50°C、估算机身停止线 35–50°C，并可启用额外的 CPU 热点停止线 70–110°C。默认电池 45°C、机身 43°C、额外 CPU 热点停止线关闭。这些是 Pulse 的退出条件，不是测得的厂商硬件极限。

任意停止条件触发后恢复原厂配置，保留原因和采样；不会冷却后自动反复重新加压。电池温度、CPU 热点和估算机身温度分别显示。GPU、充电、系统 Thermal HAL、内核/芯片底层保护均不关闭。

## 定时与持续运行

- 定时：1–1440 分钟，默认 15 分钟，到时恢复。
- 持续：没有倒计时，手动停止或温度触线时恢复。
- 持续模式可另开「重启后继续」。下次开机先恢复旧会话，再校验固件、温度和设备后重新应用；已触线停止或手动停止的会话不会因重启重新开启。
- 未开启开机继续的会话在重启后恢复。固件更新时只移除本工具自己的旧覆盖文件，不往新固件写回旧编码配置。

根守护与独立的第二守护不依赖 Activity 是否打开；前台服务提供通知及定时会话的唤醒锁。通知包含电池/机身温度、剩余时间及「恢复原厂」操作。系统强制冻结应用或休眠仍可能影响状态通知与唤醒及时性，根守护恢复运行后按系统 uptime 检查逾期。

## 记录、恢复与实现

控制台显示两组频率、上限、电池/机身/CPU 热点及温度趋势。记录页可导出真实温度、频率、上限、电流与电压 CSV；这些电池端读数不等于 SoC 功率。

运行数据保存在设备 Root 私有目录 `/data/adb/pulse-thermal`，原厂密文就地备份。APK 和源码不包含小米程序、完整配置、加密密钥或你的设备数据；适配器仅在本机从匹配的固件中读取所需材料并校验往返编码。覆盖文件只修改普通场景下的 CPU `target` 行；加载后比对正在生效的明文哈希，失败则恢复。修改前写好 KernelSU 的恢复启动脚本，恢复后清除该启动脚本。

卸载前应先点击「恢复原厂」。守护也会检查应用是否被移除；保留的原厂备份可用于恢复。连接 USB、退出温控页面和退出 Pulse 都不等于手动停止持续策略。

恢复命令（针对本工具会话，不用于删除其他工具的配置）：

```sh
adb shell su -c 'id=$(cat /data/adb/pulse-thermal/current); /system/bin/sh /data/adb/pulse-thermal/runner.sh restore "$id" MANUAL'
```

## 验证

`tools/ThermalCodecTest.java` 用设备本地提取的测试材料验证原厂往返、历史 25% 和全频配置的逐字节一致性、自定义曲线及参数边界。测试材料不进入仓库。

仪器测试显式选择 `-e thermal true` 才会写入温控配置，涵盖 UI 启动、通知恢复、真实一分钟计时、主守护被终止后的独立恢复、模拟开机恢复/继续及 CSV。普通监测回归不启用温控。真实重启与模拟启动分开报告，不把模拟结果当作已完成重启验证。

接口依据：[KernelSU 启动脚本](https://kernelsu.org/guide/module.html#boot-scripts)、[CPUFreq 策略上限](https://docs.kernel.org/admin-guide/pm/cpufreq.html)、[Android Thermal HAL](https://source.android.com/docs/core/power/thermal-mitigation)。具体控制曲线来自本机校验，不以通用文档推断其他小米固件。
