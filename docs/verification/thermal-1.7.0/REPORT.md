# Pulse 1.7.0：机身 52°C 性能优先调节

日期：2026-10-22。设备 hongkong / OS4.0.24.0.XFRCNXM，临时 KernelSU。机身读取 `thermal_message/board_sensor_temp`，CPU 热点独立读取 `cpu-*` 热区最高值。

发布行为：机身低于 52°C 放回用户选定的 CPU/GPU 上限；达到 52°C 才分级降低允许频率。首次降频 80%，持续超温约每 5 秒降至 60/40/20%，严重超温可加快降档。回落至 52°C 以下在下一次采样直接回到 100%，原解锁曲线、会话 ID 均不变。系统仍可施加其他底层限制；软件采样及热惯性可能超调，52°C 不是硬性温度钳位。

- 同一发布控制器使用 36°C 测试上限，在实际温度下降时由第 4 档直接回到 100%，50 秒内完成降频/恢复周期。每次取样核对同一会话及同一明文曲线哈希，见 `cycle.csv`、`cycle-events.txt`。
- 模拟一次 GPU 用户上限重置，1.47 秒内由 0 档补回应有的 21 档，见 `drift-repair.json`。
- 真实 EGL 重负载验证用户上限 21 档对应 274 MHz，100 次采样测得最高执行频率 274 MHz，GL 无错误。实际可用上限显示已合并热限制和用户限制。
- 实际一分钟定时结束、手动结束、独立守护接管均清除用户频率限制和临时挂载，核对原厂曲线哈希。
- 主机 dash 与 Android 实际 shell 在假 sysfs 文件上执行同一生产函数，检查精确 52°C 边界、低于上限立即释放、旧会话规则兼容、外部上限归属及小米 15 的机身停止行为。

本次没有把手机加热到机身 52°C。CPU/GPU 执行器和恢复退出测试在本版本迭代中完成；最终性能优先行为见 `hardware-report.json`。用户另报告 DevCheck 总分约 7200、常温 GPU 单项约 8100；这是用户测量反馈，本轮未复测完整 DevCheck。
