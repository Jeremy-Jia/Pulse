# 非 Root 模式与 ADB 模式

Pulse 1.3.0 支持普通权限、ADB shell 和 Root 三种访问方式。已在本次连接的 Xiaomi 18 Pro（系统报告 M610BB / hongkong / SM8950，Android 17 / OS4.0.24.0.XFRCNXM）上验证普通模式与 ADB 模式。其他固件仍需按实际权限探测。同一 APK 与 ARM64 原生组件同时适用于小米 15/18，不按机型禁用 Root 或非 Root 路径。原有小米 15 / KernelSU 的 Root 路径保留；本次小米 15 未重新连接做 Root 实机回归。ADB 激活使用 Android 内部 Binder API，已在当前 Android 17 固件验证，未来系统版本变化时可能需要适配。

## 普通模式

安装并打开 APK 即可，无须 Root 或电脑。内置 CoreMark、Dhrystone 和 Whetstone 直接以应用 UID 运行；公开的 CPUFreq、温度、GPU、内存、电池接口按可读性采集。禁止访问的节点显示「—」。

本设备普通应用无法打开 PMU，`perf_event_open` 返回 EACCES。因此普通模式的 IPC / PMU 显示不可用，CoreMark 本身仍可运行并执行 CRC 校验。CPU 整体/逐核负载依赖 `/proc/stat`，系统不开放时不可用；不会用应用自身负载伪装整机负载。

Android 限制从应用可写目录执行新导入的程序，因此自定义 ELF 需要 ADB 模式或 Root。内置程序通过 APK 的原生库安装路径执行，不受此导入限制。

## 在电脑上激活 ADB 模式

电脑需有 Python 3 与 ADB，手机已开启 USB 调试并允许此电脑。先打开 Pulse，再在源码目录执行：

```sh
python3 tools/activate-adb.py
```

连接多台设备时指定序列号：

```sh
python3 tools/activate-adb.py --serial DEVICE_SERIAL
```

此脚本通过 `app_process` 启动 UID 2000 的辅助进程，不调用 `su`。App 与辅助进程通过 Binder 通信，无 TCP 端口，也没有新增联网权限。激活入口受系统 DUMP 权限及 shell/root UID 双重检查保护，辅助进程只接受安装时解析到的 Pulse UID 的调用。调用能力不广播给其他应用。

激活会临时将 `security.perf_harden` 设为 0（与 shell 使用 simpleperf 的启用方式相同），原值保存在 `/data/local/tmp/pulse-adb-UID/perf_harden`。它不关闭 SELinux，不改变 CPU 频率、温控、调度策略或系统分区。仅采集当前系统允许的用户态 PMU；内核态、受限节点和未支持事件仍不可用。

激活后无需保持电脑连接。手机重启、强行停止 Pulse、升级安装或系统结束应用进程后，辅助进程会结束，需要再次激活。辅助进程不在后台反复启动 Pulse。若要明确停止并恢复原来的 profiling 属性：

```sh
python3 tools/activate-adb.py --stop
```

断开辅助进程后，监测回到普通模式。Root 设备仍可通过原有 KernelSU / su 路径运行。

ADB 模式的自定义 ELF 会先由应用复制到自身外部文件目录，再由 shell 复制到 `/data/local/tmp/pulse-bench-UID/case.elf` 执行；仅导入你信任的测试程序。

跑分期间使用有超时上限的 CPU 唤醒锁；性能实验室页面在测试运行时保持屏幕点亮。结束、取消、服务销毁或超时后释放唤醒锁，避免普通模式因熄屏暂停而产生失真的长耗时。厂商额外后台管理仍以固件策略为准。

## 结果口径

- cycles 与 instructions 在同一 PMU 事件组中调度。其余事件可独立复用；JSON 保留 raw、scaled、time_enabled、time_running、running_ratio 和 errno。
- PMU 覆盖正式测量子进程（包括加载、初始化和退出，以及继承的子进程）；不是仅覆盖 CoreMark 内部计时循环。不要把这里的 IPC 与不同编译选项/不同计数边界的实验混为一谈。
- IPC 是用户态退休架构指令 / 用户态周期。PMU 无权限时保持 null，不从频率或跑分反推 IPC。
- 有效 MHz 优先采用用户态周期 / task-clock，次选 wait4 返回的进程 CPU 时间；没有 PMU 时只提供实际运行核心的 CPUFreq 抽样估计。它们均有调度/内核时间及采样误差，不是固定物理时钟。
- 测试会抽样检查进程的亲和性与最近运行 CPU。若系统改变了亲和性或发生核心迁移，JSON 标注 `affinity_stable=false`，UI 显示说明，且不输出指定核心的每 MHz 成绩。这是抽样检测，无法保证识别采样之间的全部瞬时迁移。
- 单独启动 PMU 探测时也会应用指定的绑核请求。

## 悬浮窗

悬浮窗只显示所选指标，删除标题、图表、分类以及底部可用数量和刷新时间；左右留白 3 dp、上下 2 dp，宽度最低 100 dp，窄窗建议配合小字号。CPU 标签为「核0频率」「核0负载」，簇仍是独立指标。直接拖动指标区域移动，固定位置后可滚动长列表。没有选中指标时隐藏窗口。粗体开关同时作用于标签和值，预览同步实际样式。打开应用可使用桌面图标或常驻通知。

1.3.0 可在「显示与交互」开启「无边框」，仅移除悬浮窗描边，保留背景、不透明度和拖动能力，预览同步此选项。

1.5.1 增加「悬浮窗配色」卡片：名称、数值、背景三项可分别选择预设色或输入 `#RRGGBB`，独立于桌面小部件；未自选数值颜色时继续跟随主题。「恢复悬浮窗默认配色」只清除这三项自选颜色，背景不透明度与无边框设置保持不变。

拖动按完整显示边界计算，取消固定顶部留白，允许贴到状态栏/刘海区域及左右两侧；系统状态栏和刘海仍可能覆盖部分内容，可从侧边留白把窗口拖回。位置锁定与触摸穿透开启时，按原有设置禁止拖动。横竖屏或尺寸变化后会重新限制窗口位置，避免窗口整个移出屏幕。

## 桌面小部件

在悬浮窗设置页点「添加桌面小部件」或通过桌面的小部件列表添加「Pulse 实时指标」。与悬浮窗共用指标选择、字号、粗体和密度；支持缩放与滚动。不需要悬浮权限、Root 或 ADB，读取能力由当前访问模式决定。

1.3.0 可在同一设置页为所有小部件单独选择名称颜色、数值颜色、背景颜色，支持预设色和 `#RRGGBB`。背景不透明度支持 0–100%，「小部件无边框」独立于悬浮窗边框；0% 背景配合无边框可仅显示文字。恢复默认配色后，数值颜色重新跟随主题。

监测期间复用采样、最多每 2 秒更新；未监测时点按指标可刷新，系统还会约每 30 分钟请求一次刷新，受 HyperOS 调度影响。不会为小部件单独常驻采样服务。持久化最近样本用于进程重建，采样时间放在无障碍描述中。后台读取不会把权限不足的数据改为零。

## 安装签名

本次 APK 使用这台 Mac 的开发签名，与仓库历史 1.0.0 APK 的开发证书不同。当前非 Root 手机已成功安装；如果小米 15 已装历史版，覆盖更新应在原开发环境用原来的 keystore 重签本次源码构建的 APK，以保留应用数据和授权。不要为了绕过签名检查自动卸载旧版。签名差异与 Root/机型兼容是独立问题。
